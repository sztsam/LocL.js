⚡ Installation & Quick Start

LocL.js is distributed as an ESM + CommonJS hybrid package with complete TypeScript declarations and zero external dependencies.

bash 
# Using npm
npm install locl-js

# Using pnpm
pnpm add locl-js

# Using bun
bun add locl-js

1. Define Dictionaries with defineResources

defineResources leverages TypeScript 5 <const T> generic inference to preserve string literal types and automatically extract template placeholders without requiring verbose as const annotations:

typescript — src/i18n.ts 
import { initLocL, defineResources } from "locl-js";

export const resources = defineResources({
  en: {
    welcome: "Welcome back, {name}!",
    cart: {
      "=0": "Your shopping cart is empty.",
      one: "You have 1 item in your cart.",
      other: "You have {count} items in your cart."
    },
    social: "{count, plural, offset:1 =0 {No likes yet} =1 {You liked this} other {You and # others liked this}}",
    auth: { login: "Log In", register: "Sign Up" }
  },
  de: {
    welcome: "Willkommen zurück, {name}!",
    cart: {
      "=0": "Ihr Warenkorb ist leer.",
      one: "Sie haben 1 Artikel im Warenkorb.",
      other: "Sie haben {count} Artikel im Warenkorb."
    },
    social: "{count, plural, offset:1 =0 {Keine Likes} =1 {Dir gefällt das} other {Dir und # weiteren gefällt das}}",
    auth: { login: "Anmelden", register: "Registrieren" }
  }
});

export const translator = initLocL({
  resources,
  fallbackLanguage: "en",
  language: "en"
});

2. Basic Translation Execution

Translate keys with type safety, automatic variable extraction, and instant language switching:

typescript 
// 1. Parameter interpolation (strictly typed: requires { name: string })
translator.t("welcome", { name: "Alice" }); 
// => "Welcome back, Alice!"

// 2. Object plurals (exact '=0' overrides category)
translator.t("cart", { count: 0 }); // => "Your shopping cart is empty."
translator.t("cart", { count: 5 }); // => "You have 5 items in your cart."

// 3. ICU inline plurals with offset and # formatting
translator.t("social", { count: 3 }); 
// => "You and 2 others liked this"

// 4. Change language (syncs DOM & notifies all reactive subscribers)
translator.changeLanguage("de");
translator.t("welcome", { name: "Alice" }); 
// => "Willkommen zurück, Alice!"

⚙️ Configuration Options (`initLocL`)

The initLocL(config) factory configures the global or scoped translator behavior. Every option is strictly typed in TypeScript:

Option Type Default Description
resources Record<string, any> {} Initial in-memory translation dictionaries indexed by language code.
fallbackLanguage string "en" Language to fall back to when a key is missing in the active language.
language string fallbackLanguage Initial active language code.
loader ResourceLoader undefined Asynchronous loader for dynamic bundles or namespaces.
formatters Record<string, Formatter> {} Custom formatter functions accessible via pipe syntax ({val \| custom}).
strictParams boolean true Set to false for large dictionaries (10,000+ keys) to bypass recursive type-literal parsing and maximize tsc compile speeds.
onMissingKey (key, lang, chain) => void undefined Telemetry hook fired when an unlocalized key is encountered in production.
pseudoLocalization boolean \| PseudoOptions false QA layout testing mode that wraps strings in accented expansion markers (e.g. [!!! Ḩéļļö !!!]).
autoSyncDocument boolean true Automatically updates browser <html dir="..." lang="..."> attributes on language changes.
typescript 
const translator = initLocL({
  resources,
  fallbackLanguage: "en",
  strictParams: true,
  onMissingKey: (key, lang, chain) => {
    // Send to Datadog or Sentry:
    console.warn(`[i18n telemetry] Missing key "${key}" in "${lang}". Fallback chain:`, chain);
  },
  pseudoLocalization: false,
  autoSyncDocument: true
});

🔍 Scopes & Namespaces (`withConfig`)

Create lightweight, isolated translator proxies for specific namespaces or pinned languages without duplicating in-memory resource trees:

typescript 
// 1. Scoped proxy: resolves keys relative to "dashboard"
const dashboardT = translator.withConfig({ scope: "dashboard" });
dashboardT.t("title"); // Resolves "dashboard.title"

// 2. Language-pinned proxy: always renders German regardless of global language
const deTranslator = translator.withConfig({ language: "de" });
deTranslator.t("welcome", { name: "Hans" }); // Always in German

// 3. Multi-scope union: combines multiple namespaces
const multiT = translator.withConfig({ scope: ["auth", "dashboard"] });
multiT.t("dashboard.title");
multiT.t("auth.login");

🔀 ICU Inline Plural Syntax & Offsets

LocL v2.5.0 supports standard inline ICU MessageFormat plural expressions. Templates are tokenized once and cached in an execution plan, providing 10x–20x runtime throughput compared to per-call regex scanning.

typescript 
const en = {
  cart: "{count, plural, =0 {Your cart is empty} =1 {You have 1 item} other {You have # items}}",
  likes: "{count, plural, offset:1 =0 {No likes} =1 {You liked this} one {You and # other person} other {You and # other people}}",
  upload: "{count, plural, one {{user} uploaded # file} other {{user} uploaded # files}}"
};

// 1. Number substitution with '#' formatted via native Intl.NumberFormat:
translator.t("cart", { count: 0 });    // => "Your cart is empty"
translator.t("cart", { count: 1 });    // => "You have 1 item"
translator.t("cart", { count: 1250 }); // => "You have 1,250 items"

// 2. Offsets: adjusts count before plural rule evaluation and '#' replacement:
translator.t("likes", { count: 0 }); // => "No likes"
translator.t("likes", { count: 1 }); // => "You liked this"
translator.t("likes", { count: 2 }); // => "You and 1 other person" (2 - 1 = 1 -> 'one')
translator.t("likes", { count: 7 }); // => "You and 6 other people" (7 - 1 = 6 -> 'other')

// 3. Nested variable extraction:
translator.t("upload", { user: "Alice", count: 3 }); 
// => "Alice uploaded 3 files"
💡 Escaped Hash Symbol

If your translation requires a literal # character without numeric substitution, escape it as \#.

🔢 Plural Exact Quantities (=0, =1, =N)

Define explicit numeric overrides that take precedence over linguistic grammatical categories:

typescript 
const en = {
  inbox: {
    "=0": "Inbox zero! No unread messages.",
    "=1": "You have exactly one urgent message.",
    one: "You have 1 message.",
    other: "You have {count} messages."
  }
};

translator.t("inbox", { count: 0 }); // => "Inbox zero! No unread messages."
translator.t("inbox", { count: 1 }); // => "You have exactly one urgent message."
translator.t("inbox", { count: 5 }); // => "You have 5 messages."

🥇 Native Ordinal Plurals (1st, 2nd, 3rd)

Format ordinal rankings using native Intl.PluralRules({ type: "ordinal" }):

typescript 
const en = {
  rank: {
    one: "{count}st place",
    two: "{count}nd place",
    few: "{count}rd place",
    other: "{count}th place"
  }
};

translator.ordinal("rank", { count: 1 });  // => "1st place"
translator.ordinal("rank", { count: 2 });  // => "2nd place"
translator.ordinal("rank", { count: 3 });  // => "3rd place"
translator.ordinal("rank", { count: 21 }); // => "21st place"
translator.ordinal("rank", { count: 104 }); // => "104th place"

// Or using translator.t() with ordinal flag:
translator.t("rank", { count: 2, ordinal: true }); // => "2nd place"

📥 Key Extraction (`locl extract`)

Scans your source files (.ts, .tsx, .js, .jsx, .vue, .svelte) and synchronizes detected keys into your base language file (locales/en.json):

bash 
# Basic scan of src/, app/, pages/, components/
npx locl extract

# Custom source directories and file extensions
npx locl extract --src src,components --ext ts,tsx,vue --locales locales --base en

# Prune orphaned keys no longer used in code
npx locl extract --clean

# Generate flat dot-notated JSON instead of nested objects
npx locl extract --flat

# Provide fallback placeholder value for newly created keys
npx locl extract --default "TODO"

🛡️ Parity & Parameter Linting (`locl check`)

Verifies that all secondary language dictionaries implement every key present in the base language dictionary:

bash 
# Fails in CI with exit code 1 if keys are missing
npx locl check --locales locales --base en

# Deep linting: checks that template tokens and XML/JSX tags match 1:1
npx locl check --lint-params

# Strict mode: fails if orphaned or empty string keys are found
npx locl check --strict

# Automated backfill: populates missing keys copying base values
npx locl check --fix

🤖 Automated AI Machine Translation (`locl translate`)

Automatically backfills missing translations from your base dictionary using modern AI and machine translation providers:

bash 
# DeepL translation (default provider):
npx locl translate --target es,de

# OpenAI (default model: gpt-4o-mini):
npx locl translate --target es,fr --provider openai --model gpt-4o

# Local Ollama instance (e.g. Llama 3) with zero cloud fees:
npx locl translate --target de,ja --provider ollama --model llama3

# Google Cloud Translation API:
npx locl translate --target zh,it --provider google

# Force re-translation:
npx locl translate --target es --force

# Dry run preview:
npx locl translate --target es --dry-run
🛡️ Smart Token & Tag Masking

Machine translation APIs often mangle variables (turning {count} into {cuenta}) or corrupt HTML tags. LocL shields all placeholders ({name}, {{name}}, {var | upper}) and JSX tags (<bold>...</bold>) as __LOCL_TOK_0__ before invoking APIs, restoring them with 100% precision in the translated output.

📦 Ahead-of-Time Bundle Compilation (`locl compile`)

Bundles separate JSON files into a single optimized TypeScript or JavaScript file for zero runtime network delay:

bash 
# Compile to TypeScript bundle

# Compile to ESM or CommonJS
npx locl compile --format esm --output dist/locales.js

🔗 Localized Navigation (<Link /> & useLocalizedPath)

Automatically rewrite URLs to respect active languages and routing prefix strategies ("as-needed", "always", "never"):

tsx 
import { Link, useLocalizedPath } from "./i18n-react";

export function Navigation() {
  const getPath = useLocalizedPath("as-needed");

  return (
    <nav>
      {/* If 'en' is default: href="/about". If 'de' is active: href="/de/about" */}
      <Link href="/about">About Us</Link>

      {/* Explicit target locale */}
      <Link href="/pricing" locale="fr">Tarifs</Link>

      {/* Force prefix even on default locale */}
      <Link href="/contact" prefixStrategy="always">Contact</Link>

      {/* Programmatic path helper */}
      <button onClick={() => window.location.href = getPath("/dashboard")}>
        Dashboard
      </button>
    </nav>
  );
}

💧 SSR Hydration & Zero-Flicker Bootstrapping (<LocLHydrate />)

Eliminate hydration mismatches and unlocalized flash in SSR and Next.js applications by embedding the server's dehydrated translation payload:

tsx — src/components/ClientRoot.tsx ("use client") 
import React from "react";
import { LocLProvider, LocLHydrate } from "locl-js/react";
import { translator } from "@/i18n";

export function ClientRoot({ state, children }: { state: any; children: React.ReactNode }) {
  return (
    <LocLProvider translator={translator}>
      <LocLHydrate state={state}>
        {children}
      </LocLHydrate>
    </LocLProvider>
  );
}

📦 Server State Dehydration (`dehydrate`)

Extract server translator state to pass down to client hydration components:

tsx — app/[locale]/layout.tsx (Server Component Layout) 
import { getTranslator, dehydrate } from "@/i18n-server";
import { ClientRoot } from "@/components/ClientRoot";

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const t = await getTranslator();
  const dehydratedState = dehydrate(t); // { locale: "de", resources: { de: { ... } }, direction: "ltr" }

  return (
    <html lang={dehydratedState.locale} dir={dehydratedState.direction}>
      <body>
        <ClientRoot state={dehydratedState}>
          {children}
        </ClientRoot>
      </body>
    </html>
  );
}

⛓️ Multi-Pipe Formatter Chaining

Chain multiple formatters sequentially from left to right using pipe (|) operators:

typescript 
const en = {
  user: "User: {name | trim | upper | truncate:8, ...}"
};

// Input: "   alexander   "
// Step 1: trim     -> "alexander"
// Step 2: upper    -> "ALEXANDER"
// Step 3: truncate -> "ALEXA..."
translator.t("user", { name: "   alexander   " }); 
// => "User: ALEXA..."

📑 Full API Reference

Exhaustive TypeScript API reference for all exported modules in LocL.js v2.5.0.

Core Package (`locl-js`)

initLocL<T, Fallback, S, F, Strict>(config: LocLConfig): LocL

Initializes and returns a new LocL translator instance with pre-compiled template plans.

ParameterTypeDescription
configLocLConfigConfiguration options including resources, fallbackLanguage, loader, formatters, and telemetry hooks.
defineResources<const T>(resources: T): T

Identity helper that preserves literal string types without requiring manual as const annotations.

defineStrictResources<const T>(resources: T): T

Identity helper that enforces complete translation parity across all secondary languages against the fallback language at compile time.

createRemoteLoader(options: RemoteLoaderOptions): RemoteLoaderInstance New in 2.5.0

Creates an Over-The-Air remote translation loader featuring Stale-While-Revalidate (SWR) caching and offline resilience.

flattenDictionary(obj: Record<string, any>): Record<string, any>

Flattens a deeply nested dictionary into a single-level dot-notated object while preserving plural objects ({ one, other }).

unflattenDictionary(flat: Record<string, any>): Record<string, any>

Reconstructs deeply nested dictionary objects from dot-notated keys while protecting against prototype pollution.

`LocL` Instance Methods

translator.t(key: string, values?: object, format?: object): string

Translates a key, handles interpolation, formatters, ICU inline plurals, and exact quantity rules.

translator.plural(key: string, values: { count: number }, format?: object): string

Translates a key with cardinal plural rule evaluation.

translator.ordinal(key: string, values: { count: number }, format?: object): string

Translates a key using native ordinal rules (1st, 2nd, 3rd).

translator.changeLanguage(lang: string): void

Updates active language, synchronizes document attributes in browser, and notifies subscribers.

translator.getDirection(lang?: string): "ltr" | "rtl"

Returns the script direction ("ltr" or "rtl") for the active or queried locale.

translator.withConfig(config: { scope?: string | string[], language?: string }): LocL

Returns a lightweight, cached proxy instance scoped to a namespace or pinned to a specific language.

translator.subscribe(listener: (newLang, prevLang, meta) => void): () => void

Subscribes to language and resource updates. Returns an unsubscribe function.

React Bindings (`locl-js/react`)
